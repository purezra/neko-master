# 设备访问明细与定向导出

设备页提供“设备概览”和“访问明细”两个标签页。访问明细可组合筛选设备或设备分组、域名或目标 IP、规则及顶层策略组，支持分页和按上传、下载、总流量、连接数、最后活动时间排序。查询使用已保存的完整时间桶，显示的实际范围与导出保持一致。

趋势弹窗支持折线或平滑曲线、上传或下载或总流量。分设备模式下可点击图例隐藏曲线，也可选择任意单台设备，包括总量前十以外的设备。“全部设备”仍显示前十台及其余设备的合计。

导出页可选择全部设备、单台设备、命名分组或未分组设备。指定范围后只允许设备统计和设备访问明细，避免混入网关全局统计；JSON 元数据保留设备范围，文件名也会带上范围。Excel 可开启“每台设备独立工作表”。格式、数据项、Top 数量、设备范围及分表设置在当前浏览器中按网关保存。Top 数量只限制汇总榜单，访问明细最多 100,000 行，超限会停止导出并提示缩小范围。

## 原始规则与历史兼容

- `rule` 继续使用原有统计口径：多跳连接是顶层策略组。流量统计与规则链图不会改为按原始规则聚合。
- `matchedRule` 和 `rulePayload` 单独保存网关上报的原始规则和参数。两个不同原始规则经过同一策略组时，明细会分别计数。
- 旧数据无法补出原始命中规则，查询显示“未记录”，导出的原始字段为空。网关未上报原始规则时同样为空。
- 采集缓冲及现有 agent 协议已经包含规则和参数，本次没有改变 agent 载荷或协议版本。

SQLite 启动时会在一个事务中升级分钟和小时事实表的复合主键并恢复索引，保留旧计数；失败会整体回滚，下次启动可重试。原始规则沿用原表的保留期限与网关删除逻辑。

ClickHouse 自动建表开启时会给 `traffic_detail` 和 `traffic_detail_buffer` 同步增加 `matched_rule String DEFAULT ''`、`rule_payload String DEFAULT ''`。禁用自动建表（`CH_AUTO_CREATE_TABLES=0`）的部署须在升级前对这两张表执行相同的 `ADD COLUMN IF NOT EXISTS`。历史行读取为空字段。
